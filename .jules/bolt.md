# Bolt's Journal - Allrated Cinema Performance Optimization

## 2025-02-18 - Resetting IntersectionObserver State for Infinite Scroll
**Learning:** Standard intersection observer hooks (like `useHasIntersected`) that stay permanently set to `true` after first intersection work fine for static lazy-loaded images, but cause massive performance degradation, eager continuous rendering loops, and excessive API/network traffic when used for infinite scroll sentinels. When more items are appended, pushing the sentinel out of viewport, the sentinel's visibility state MUST transition back to `false` so it can trigger a new load only when it actually enters the viewport again. Otherwise, whenever any other component state dependencies (such as the current page or loading state) change, the effect triggers immediately regardless of viewport position.
**Action:** Extend custom intersection observer hooks to support a `triggerOnce` option (defaulting to `true` for lazy loading of images and deferred rows, which disconnects immediately to save DOM observation overhead), and set it to `false` for active scroll sentinels so that state correctly resets to `false` when out of view.

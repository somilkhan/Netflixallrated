## 2025-02-18 - Optimized Intersection Observer DOM Overhead
**Learning:** In highly visual movie search and discovery platforms, horizontal list rows and thousands of static poster image elements can easily overwhelm the main thread if they remain actively observed by `IntersectionObserver` instances even after entering the viewport. By supporting a `triggerOnce` option in the custom `useHasIntersected` hook (enabled by default for images/rows), we can instantly disconnect the observer on first intersection, reducing continuous browser observation overhead and garbage collection pressure.
**Action:** Always enable `triggerOnce` for lazy-loaded content that doesn't need to exit and re-enter view, but preserve non-triggerOnce behaviors (e.g. `triggerOnce: false`) for repeating infinite scroll sentinels that rely on scroll re-entry.
